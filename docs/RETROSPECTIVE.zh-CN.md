# 从 SGLang 兼容迁移到 DeepSeek 1017 验证

[English](RETROSPECTIVE.md) · [项目总览](../README.zh-CN.md) · [工程手册](ENGINEERING.zh-CN.md) · [测试总览](../TESTING.zh-CN.md)

本文整理于 2026-11-05，解释本项目为什么修改、如何判断问题及哪些结论仍未成立。实际操作见工程手册，逐项测试数据见 TESTING。工作针对推理软件和部署策略，固定模型修订不变，没有微调或重新训练权重。

## 1. 从哪些工作继续

[ormandj 的 V4.1/1017 项目](https://github.com/ormandj/sglang-deepseek-v41-flash-sm120)已提供固定源码、构建栈、SM120 补丁、DSPARK/SPS 和 TP4/EP2 配方。[Ombori 的 0731 项目](https://github.com/ombori/deepseek-v4-flash-0731-sglang-4x-rtx-pro-6000)提供旧版部署和正确性补丁经验。我们据此做版本兼容核对、迁移、回归、构建集成、部署和验证；没有把上游算法或全部内核优化重新署为自己的成果。[NOTICE](../NOTICE.md)、补丁原文及上游 PR 引用保留归属。

目标不是把旧版参数和代码整体搬到 1017。新版 SGLang 已改变部分字段、布局、接口和实现，旧补丁有些已经等效存在，有些不再适用。完整 33 项审计结果为 7 项迁移、22 项已有等效实现、4 项不适用，详见[迁移记录](../compat/migration.json)。

## 2. 兼容迁移先回答“当前代码还缺什么”

| 问题 | 处理与取舍 | 可追溯依据 |
| --- | --- | --- |
| 推测解码接受多个 token，惩罚状态不能仍近似按一个推进 | 累计实际已提交输出；覆盖批复用、过滤和合并，按实际 logits 符号应用重复惩罚 | [惩罚](../patches/33-compat-verify-penalties.patch)、[状态](../patches/34-compat-committed-penalty-state.patch) |
| 最后一个分片可能携带完整名称和参数，多工具不能只补最后一个 | 补齐所有工具收尾，并保证重复调用不重复发出 | [工具收尾](../patches/35-compat-tool-final-flush.patch) |
| 普通正文中的标签可能被 SSE 分片拆开 | 补齐普通正文状态的前缀暂存，复用当前结束刷新逻辑 | [标签前缀](../patches/36-compat-reasoning-prefix.patch) |
| 请求切片丢失路由字段 | 保留已有请求的 routing_key，避免引入另一套路由策略 | [请求字段](../patches/37-compat-request-routing-key.patch) |
| 最小预热形状也可能超过预算；退化分数可能留下非法候选 id | 只选可容纳的受支持形状；保持草稿 token id 在词表内 | [预热](../patches/38-compat-deepgemm-warmup-budget.patch)、[sentinel](../patches/39-compat-draft-sentinel.patch) |

这些修改主要建立正确性边界。回归通过不等于已证明吞吐提升；41 个当前 SGLang 补丁也不能简单等同于 41 个本项目新增优化。

## 3. 构建可靠性也是交付的一部分

FlashInfer 构建中存在外层安装与内部安装的锁等待风险，因此先安装固定源码声明的编译依赖，再启用 `FLASHINFER_BUILD_NO_PIP=1`。Triton 的目标测试构建选项需要通过实际支持的 `TRITON_APPEND_CMAKE_ARGS` 传给 CMake，而不是仅设置一个未生效的环境变量。大量重复 cubin 日志另作过滤，但保留 `pipefail`，不能把失败隐藏成成功。

镜像源和源码缓存提升受限网络中的可构建性，前提仍是核对基础镜像 manifest/config/层以及源码提交、补丁和结果树。发布时复用已测产物，核对所有 79 个运行层，避免“测试一个镜像、发布另一个重建镜像”。本地索引包含构建证明而发布物只含运行平台清单，摘要不同有明确解释，见[回执](../compat/publication.json)。

验收分层保留：本地源码体 CPU 279 项；镜像内 CPU 1198 项及 691 个子测试、跳过 1 项 CUDA 专用检查；另有 8 项原生 CUDA 检查。这些数量不能相加成一个统一模型质量得分。完整联网来源校验命令曾因网络失败未完成，另行核验通过的部分有独立记录，也不能把它改写为所有步骤一次通过。

## 4. 工具参数：解析正确与生成正确是两件事

用户要求工具参数原样包含 `<think>literal</think>` 时，观察到字面量损坏，某次修改版甚至没有返回工具调用。先沿请求编码、原始 token、推理解析、工具解析和 API 输出逐层检查，而不是看到 HTTP 200 就判定成功。

rc.4 的[解析修复](../patches/41-v41-tool-literal-reasoning.patch)把工具体内字面量与结构性推理标记区分开，并验证不同分片不会改变参数。候选测试中解析器造成的参数损坏为 0，但专项端到端通过率依然很低，因此结论只覆盖解析保真。

后续 442 次诊断中，20 条实际输入与官方编码器逐 token 一致。复现失败位置在语法掩码之前，目标模型已偏向错误闭合标记；正确标记仍被允许，去掉工具语法的原生生成也能复现错误。关闭 DSPARK 或使用 low 思考仍不能保证保真。证据不足以支持另一个透明框架补丁，故没有从提示里重建参数来掩盖原始输出。[诊断依据](../compat/validation.json)中的 `literal_generation_diagnosis` 保留计数与数值配置边界。

## 5. 代码题：先比较请求策略

温度 0 的代码题曾耗尽 12,288 输出 tokens，却没有最终代码。推理 token 也计入预算，因此不能把它直接解释为传输或解析丢代码。

我们固定 8 道小型代码题、每题 5 次、并发 1、top_p 1 和预算 12,288，在 DSPARK 开关两种模式下分别比较温度与思考强度。temperature 1 / low 两侧均通过 40/40；temperature 0 / high 仍有截断，关闭思考也出现代码错误。完整四组计数见测试总览。

因此提供了[可选请求预设](../examples/code-request-profile.json)和[客户端示例](../examples/code-request.py)，而不是修改全局默认值。客户端保留显式覆盖，拒绝截断和空最终正文，不把 reasoning 当代码，不自动重试替换失败结果。这是小型代码题上的策略选择，不是通用代码能力或字面量保真的保证。

## 6. 并行参数：用同模型实验检验直觉

0731 的 TP4 / Attention DP4 / EP4 能运行，并不说明 1017 套用后更快。后续用同一 rc.4 镜像、同一 1017 权重、每实例四卡比较原配置与 Attention DP4 / EP4。原配置保留 TP4 / Attention DP1 / EP2、DSPARK block 5、SPS auto 和显存比例 0.85；实验侧开启 DP LM Head，并因 KV 分配需求提高到 0.90。

完成的中文解释短输入测速中，C1/C4/C8 均为原配置合计吞吐较高；204 次主质量请求也已完成。操作方在 18/48 组测速后结束实验，C16、代码测速及追加 low 复测没有完成。具体数值、三轮中位数、首 token 等待时间和缓存口径见[并行记录](../compat/topology-comparison-20261103.json)。

DP、EP、LM Head、显存比例、GPU/NUMA 分组和派生调度参数同时变化，不能把差异全部归因于 DP。最终保留的是已完成负载下较合适的整套配置，不是对所有并发、长上下文和八卡拓扑的最优证明。

独立的 0731/1017 对照还改变了模型、框架、DSPARK block 和资源限制，只能用于描述两套部署。[部署对照](../compat/deployment-comparisons-20261103.json)与同模型实验分开保存，不混用速度和得分。

## 7. 结论与继续工作的边界

- 已交付：兼容迁移、构建集成、V4.1 工具体解析修复、可选代码请求策略、共享主机启动配方、验证与发布回执。
- 已知限制：模型仍可能生成错误字面量；复杂代码仍可能耗尽预算；固定 seed 不代表严格确定性；小型合成结果不代表生产吞吐或普遍质量提升。
- 未完成：1M/256K 同负载对比、TP8、同一 1017 的 DSPARK block/SPS 扫描、完整 1M 压力、长上下文和持续负载测试。
- 维护原则：权重、源码、镜像和运行配置分别标识；缓存命中和实际请求分别验收；用新的证据更新结论，不把未完成项目写成已验证。

当前候选为 `ghcr.io/loon-hejw/sglang-deepseek-v41-flash-sm120-compat:v0.4.4-rc.4`。后续变更需遵循[构建与发布规则](../BUILDING.md)，具体使用方式见工程手册。本文只归纳已记录的工程经验，不发布内部地址、凭据或原始对话。
